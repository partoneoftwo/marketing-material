01 It only reads

Nothing is installed in your cloud, and nothing in it is changed.

A scanner looks at how your cloud accounts are set up, using a role that can read and nothing more. Cloud takes what the scanner found and makes it readable. It never creates, changes or deletes a resource, and it fixes nothing on its own.

  • The scanner is Prowler, the open-source cloud security scanner, and stays a separate system
  • AWS, Azure, Google Cloud, Kubernetes and Microsoft 365 in the same report
  • Hundreds of checks: identity, storage, networks, encryption, logging
  • Runs on your own server
  1. Cloud accounts
  2. Read-only role
  3. Scanner
  4. Many Worlds Cloud
  5. Risks, incidents, tasks

02 Can these results be trusted?

The report starts by saying how completely each account could be scanned.

An account that looks clean because the scanner was refused access must never read as an account with nothing wrong. So every report opens with what was scanned, when, and which checks could not run, and says whether the figures below are complete or lower bounds.

  • Accounts scanned, and when each was last scanned
  • Checks that could not run, and the permission each one was missing
  • If a scan fails, the report still builds and says what is missing

03 Findings, ranked by severity

Each finding comes with why it matters, what to do and the evidence.

A finding is something in your cloud that needs a decision. The worst come first, and each one names the resources behind it.

  • Open storage, administrators without multi-factor authentication, old access keys, databases facing the internet
  • Trends against the scan before, so you can see whether risk is going up or down
  • PDF, Excel and PowerPoint from every page

04 One report, three readers

Leadership and cloud owners ask different questions. Each gets its own view.

The executive summary answers in a page. The cloud owner view goes down to the single resource. The full report carries the evidence for whoever does the work.

Questions for leadership

  • Is risk going up or down?
  • Do we know what is running in our cloud?
  • Is anything open to the internet that should not be?
  • Who has administrator access?
  • Is our data encrypted?
  • Are logs kept, so an incident can be investigated?
  • Which accounts need attention first?
  • Where do we stand against the frameworks we answer to?

Questions for cloud owners

  • Which resources failed which check?
  • What changed since the scan before?
  • Which failures are new, and which were fixed?
  • Which keys and roles are unused or too powerful?
  • Where is encryption missing?
  • Where is logging missing?
  • Which network rules are open to everyone?
  • What is the fix for each finding?

05 Compliance

The same findings, read against the frameworks you answer to.

One scan answers many auditors. Cloud shows which requirements of each framework are met, which are failing and which could not be assessed, with the findings behind every one.

  • Frameworks such as CIS, ISO 27001, NIS2, GDPR, SOC 2, PCI DSS and ENS
  • A failing requirement opens the findings that caused it
  • Not assessed is never shown as met

06 Conclusions

The report ends in three lists somebody can act on.

Risks go to a register, incidents to a SOC, tasks to a queue. Every rating carries the rule that produced it, because these are first readings from one scan and the page says so.

  • Send the three lists to a SpaceRisk register with one button. Nothing is sent until it is pressed
  • Sending again updates what was sent before and never makes a second copy
  • Exports for a SIEM (OCSF) and for Jira, ServiceNow or a mailbox, plus Excel and PowerPoint

For the risk register

Risks

A standing weakness, rated likelihood times consequence, each from 1 to 5, and given to an owner.

For the SOC

Incidents

Something that is exposed right now and needs responding to.

For a queue

Tasks

One piece of work with a queue, a due date and a way to tell when it is finished.

07 Every account at once

Rank your cloud accounts by what needs deciding.

With more than one account, subscription or project you get them side by side: which needs attention first, what is true at several of them against what is true at one, and which could not be scanned completely.

  • Each row opens that account's own report
  • Findings shared by several accounts are shown together
  • Unscanned is never shown as clean
